# 双向关联协议

## 1. 关联目标

记忆层和知识库必须形成双向可追溯关系：

```text
记忆 → 知识：提取、整理、标准化、验证
知识 → 记忆：引用、检索、校验、反馈、修正
```

任何由记忆生成的知识，都必须能回到来源记忆；任何被任务使用的知识，都应能记录使用结果和新反馈。

## 2. 关联类型

使用 Markdown 链接和元数据同时表达关联：

- `derived_from`：知识由记忆整理而来
- `supports`：记忆支持某项知识或决策
- `references`：知识引用另一份知识或记忆
- `used_by`：知识被某个工作流或任务使用
- `validated_by`：知识由某次测试、审查或任务验证
- `contradicts`：两个内容存在冲突，不能静默合并
- `supersedes`：新知识替代旧知识
- `feedback_for`：执行反馈用于修正某份知识

## 3. 最小关联格式

记忆文件：

```yaml
related_knowledge:
  - id: KB-20260926-0001
    relation: derived_from
    path: ../knowledge/KB-20260926-0001.md
```

知识文件：

```yaml
source_memory:
  - id: MEM-20260926-0001
    relation: derived_from
    path: ../memory/MEM-20260926-0001.md
```

正文中还应保留可读链接：

```markdown
来源记忆： [MEM-20260926-0001](../memory/MEM-20260926-0001.md)
```

## 4. 冲突处理

发现冲突时：

1. 不覆盖旧内容。
2. 在新内容中标记 `contradicts`。
3. 比较来源、适用范围、更新时间和验证结果。
4. 形成新的决策或知识版本。
5. 将旧知识标记为 `deprecated` 或 `archived`，保留历史链接。

## 5. 关系完整性检查

定期检查：

- 每份知识是否至少有一个来源或明确标记为原生知识
- 每条来源记忆是否能打开
- 双方 ID 是否一致
- 失效知识是否仍被工作流引用
- 被 `supersedes` 的旧版本是否已降级
- 任务反馈是否回写到记忆层
